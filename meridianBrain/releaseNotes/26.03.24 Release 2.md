# 26.03.24 Release 2

> **Meridian:** WIP / archive — human release notes; not read by CLI or Copilot `#file:`.

Date: 2026-03-24

## Overview

This update focuses on improving the quality of Copilot feedback tickets. The release turns the feedback flow into a more structured, interactive experience, adds clearer guidance for mining active conversation context, and reformats the resulting ADO Issue into a more polished, business-readable proposal style.

## Feature: Interactive Feedback Interview Workflow

### What

This release significantly upgrades the `/util-feedback` prompt so it no longer behaves like a simple intake form.

The updated workflow now:

- Reviews the active conversation before asking questions
- Builds a draft feedback packet from existing context when possible
- Uses structured interactive questions for missing or ambiguous details
- Breaks the interview into staged steps for orientation, detail gathering, and approval
- Requires explicit user approval before creating the ADO Issue

The prompt also now captures a much richer set of inputs, including:

- User goal
- Actual behavior
- Why the behavior was a problem
- The requested change
- Team or workflow impact
- Optional business or leadership impact
- Evidence from the conversation
- Requested next step

### Why

This improves the quality of the feedback loop substantially. Instead of generating sparse tickets that require follow-up interpretation, the prompt now works to produce a complete, high-signal summary that prompt owners can act on directly.

## Feature: Proposal-Style Feedback Ticket Formatting

### What

The feedback description template was redesigned so created Issues read more like a concise internal improvement request than a raw bug form.

The rendered output is now organized into these sections:

- `The Problem`
- `The Ask`
- `Why This Matters`
- `Expected vs Actual`
- `Evidence`
- `Requested Next Step`

Within `Why This Matters`, the template now separates impact into:

- `For us`
- `For the business`

This gives the final ticket a clearer narrative and makes the request easier to review in leadership or triage workflows.

### Why

Formatting matters because good feedback is only useful if it can be understood quickly. The new structure makes each ticket easier to scan, easier to prioritize, and easier to connect to a meaningful improvement request.

## Feature: Conversation-Aware Feedback Synthesis

### What

The feedback prompt now includes explicit instructions to reuse context from the active thread whenever it is invoked inside an existing conversation.

That includes extracting:

- The likely prompt involved
- What the user was trying to do
- What the model actually did
- Supporting evidence already visible in the conversation
- Relevant file paths, ticket IDs, errors, or workflow context

It also includes a quality bar that prevents weak, vague feedback from being submitted without additional clarification.

### Why

This reduces friction for users and increases the usefulness of submitted feedback. People should not need to restate information that already exists in the thread, and prompt owners should not have to guess at what actually happened.

## Feature: Feedback Routing and Help Text Updates

### What

This release also updates the surrounding workflow guidance so the new behavior is discoverable and consistent.

That includes:

- Parenting all created feedback Issues to work item `246209`
- Updating `/util-help` to describe the new staged interview and proposal-style output
- Preserving the existing `Copilot-Feedback` tag and area path behavior

### Why

The prompt changes are more valuable when the surrounding guidance matches them. These updates make the workflow easier to understand, easier to trust, and easier to triage consistently once the feedback enters ADO.
