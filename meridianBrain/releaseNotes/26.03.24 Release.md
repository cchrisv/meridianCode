## Overview

This update is focused on one practical outcome: managing Azure DevOps backlog order directly from the workflow repo. The release adds a dedicated backlog reorder service, new CLI commands for viewing and validating backlog rank health, interactive prompt entry points for backlog operations, and the supporting config and documentation needed to make those workflows discoverable.

## Feature: ADO Backlog Reorder CLI

### What

This release adds a new backlog reorder implementation under the workflow CLI. The new capability introduces four commands:

- `ado-tools backlog`
- `ado-tools reorder`
- `ado-tools reorder-bulk`
- `ado-tools backlog-validate`

Together these commands can:

- Read a scoped backlog for an ADO area path
- Detect whether the process uses `StackRank` or `BacklogPriority`
- Move a single work item to a target position
- Rewrite backlog rank values in bulk
- Validate rank health and optionally repair spacing issues

The CLI output was also expanded to include useful operational detail such as board column, assignee, parent work item, comment count, created and changed dates, and summarized rich text content when requested.

### Why

Backlog ordering is one of those tasks that usually becomes manual, brittle, and hard to audit. Adding it to the CLI makes the operation repeatable and visible. It also reduces the chance of ad hoc rank edits that solve a one-off problem but leave the backlog in a worse state later.

## Feature: Interactive Backlog Management Prompts

### What

The prompt catalog now includes four backlog-focused utilities:

- `/util-backlog-view`
- `/util-backlog-reorder`
- `/util-backlog-reorder-single`
- `/util-backlog-validate`

These prompts are designed to guide users through backlog inspection, single-ticket moves, bulk reorder operations, and validation flows using structured interactive questions rather than freeform chat.

The update also includes a planning prompt for the backlog reorder work so the implementation approach is documented alongside the prompt assets.

### Why

The CLI gives the repo the raw capability, but the prompts make it usable in day-to-day workflow. They reduce the amount of command knowledge a user needs to carry around and make destructive operations safer by emphasizing preview and confirmation before changes are applied.

## Feature: Backlog-Aware Types and Validation Support

### What

The workflow codebase now includes backlog-specific types, validation schemas, and field constants needed to support these operations cleanly.

That includes support for fields such as:

- `Microsoft.VSTS.Common.StackRank`
- `Microsoft.VSTS.Common.BacklogPriority`
- `Custom.DevelopmentSummary`
- `System.BoardColumn`

New backlog models and validation rules were added so query, reorder, and validation operations can be expressed explicitly instead of passing around loosely shaped payloads.

### Why

This is an important internal quality improvement. The new commands depend on more than just moving ranks around. They also need consistent field access, predictable validation, and enough typed structure to keep the service layer maintainable as the backlog workflows evolve.

## Feature: Documentation and Config Refresh for Backlog Operations

### What

The release updates the main documentation and instruction surfaces so the new backlog functionality is visible where users already look for guidance.

That includes updates to:

- `README.md`
- `.github/copilot-instructions.md`
- `.github/prompts/util-help.prompt.md`
- `config/shared.json`

The config now exposes named ADO area paths and CLI command aliases for the new backlog operations, while the docs and help content describe when and how to use them.

### Why

Without these updates, the implementation would exist but stay effectively hidden. Surfacing the commands in config, help, and instructions is what turns the feature from internal code into an actual supported workflow.

## Feature: Automated Test Coverage for Backlog Reordering

### What

This release adds a dedicated Vitest file covering backlog reorder behavior. The tests focus on rank field detection, batching behavior for backlog retrieval, sorting rules, and insertion-rank calculations.

### Why

Backlog ordering logic is easy to get mostly right and still break in edge cases. Adding targeted automated coverage helps protect against regressions in the rank detection and reorder calculations that are central to this release.
